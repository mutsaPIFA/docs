## 문서 배치 규칙

> **여러 역할이 함께 보는 문서만 이 레포. 역할 전용 문서는 해당 역할 레포로.**

| 성격 | 위치 |
| --- | --- |
| 팀 공용(계약·아키텍처·리서치) | **`docs`** (여기) |
| 백엔드 구현 상세 | `backend/docs` |
| AI 구현 상세 | `ai/docs` |
| 프론트/디자인(예: Figma 컨벤션) | `frontend/docs` |

## 협업

- **브랜치 전략: `main`(최종 데모) / `dev`(통합) / `feature/*`(작업).** PR base는 `dev`. 상세 → [`conventions/브랜치-PR-커밋.md`](conventions/브랜치-PR-커밋.md).

### ⚠️ 계약(`api-v1.md`) 변경 절차

프론트·AI가 이 문서를 보고 **동시에 병렬로** 개발한다. 조용히 고치면 남의 작업이 깨진다.

1. `feature/*` 브랜치 → **PR (base `dev`)** — main·dev 직접 푸시 금지
2. **영향받는 역할을 리뷰어로 지정** — 프론트가 쓰는 필드가 바뀌면 프론트, AI 응답 모양이 바뀌면 AI
3. PR 본문에 **무엇이 어떤 화면에 영향을 주는지** 한 줄
   > 예: "`POST /looks` 이미지 비동기 전환 — 화면 16에 폴링 필요"
4. 머지 후 팀 채널에 공유
